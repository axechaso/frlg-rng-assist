# FRLG RNG Assist 0.7.3

[简体中文](README.md) | [日本語](README.ja.md) | [English](README.en.md)

PokeLDN向けの独立したサードパーティ製プラグインです。RNG消費数の範囲と条件を設定すると、ゲーム画面にseedとカウントダウンを表示し、指定したタイミングで1回だけ入力します。最後の決定位置までは自分で移動してください。**ホウオウは↑、それ以外はA**を入力します。Bを押し続ける必要はありません。

実機テスト用のビルドです。ソフトウェアテストやオフラインでのホスト検証は、実機のタイミング検証を代替しません。[検証記録（英語）](docs/VALIDATION.md)と[実機テスト手順（中国語）](docs/HARDWARE_TEST_ZH.md)を参照してください。

## インストールと表示言語

PokeLDN v0.39.1 / API 1.11を使用してください。Plugins → Add a pluginから**frlg-rng-assist-0.7.3.pokeplugin**を選択します。インストール済みの場合はプラグインのカードから更新できます。対応するゲームはSwitch英語版・フランス語版のrev 0A、BPRE・BPGE・BPRF・BPGFです。Wirelessファームウェア1.8.0を引き続き使用できます。コンパイル済みコードを同梱しているため、利用者がPythonやARMコンパイラを用意する必要はありません。

ツール名、説明、分類、場所、ポケモン名、性格、出力は**中国語・日本語・英語**に対応し、PokeLDNのApp languageに従います。言語を変更したらPokeLDNを再起動し、プラグインを読み込み直してください。それ以外の表示言語では英語を使用します。中国語・日本語の表示には、対応するPokeLDNの言語パックが必要です。これは画面表示の翻訳であり、対応ゲームは上記の英語版・フランス語版のままです。インストールカードの概要には三言語共通の文章を使用します。

Games → FireRed & LeafGreenには次の2つのツールを表示します。

1. **RNG：検索と時刻指定入力**：検索条件を注入し、候補を検索してカウントダウン後に1回入力します。
2. **RNG：PIDから実際の消費数を逆算**：その試行の初期seedと実際のPIDを手入力し、実際の遭遇開始位置を調べます。ゲーム機への接続や個体値の入力は不要です。

対象は、御三家、化石、もらう・購入、ゲームコーナー、通常の固定シンボル、伝説の固定シンボル、イベント、徘徊個体の初期化、野生、アンノーン、その他の固定対象に分類しています。固定・ギフトは**Method 1 / 4**、野生は**H1 / H2 / H4**を選択できます。野生では、あまいかおり・各つりざお・いわくだきと場所を選びます。アンノーンは別途、部屋を選択します。

## 1回の試行

1. 対象の近くでセーブします。OPTIONS → BUTTON MODEを**L/R**に設定し、ゲームを再起動して他のboostsを解除します。
2. PCでゲーム、分類、対象または野生の場所、検索範囲を選びます。最初のテストでは色違い以外も許可し、性格・個体値は指定しないでください。対象・場所の横にプリセットOffsetが表示されます。手動Offsetを空欄にするとプリセットを使用します。
3. PCでStartを押します。ゲーム機でMystery Gift → Wonder Cards → Friend → POKELDNを選び、インストール応答**0x524E4703**を待ちます。
4. 通常の操作でタイトル画面に戻り、つづきから再開します。消費数0はタイトルで確定した実際の初期seedです。フィールドに戻った時点では、通常すでに0を超えています。
5. 最後の決定位置まで自分で移動し、ボタンを離して待ちます。三鳥は対象の目の前、ミュウツーは会話の最後のボタン待ち、あまいかおりは手持ちメニューの該当項目で待機します。釣りは、それ以前の確認を自分で進めてください。ホウオウは発動マスの1マス南で上を向いて待機します。
6. 実際にイベント・遭遇が始まったか確認します。捕獲後はRで実際の個体値、L+Rで手持ちの最後のポケモンのPIDを確認し、2つ目のツールに手入力して照合します。

位置、向き、話しかける対象、スクリプトの入力待ちは検出しません。移動、メニュー操作、釣りの繰り返しも自動化しません。生成時の入力は1回だけです。捕獲検索を事前に読み込んでいれば、同じ戦闘中に投球を有効にできます。ソフトリセットやゲームの終了で注入は消えるため、次の試行では再インストールが必要です。新規セーブでは、御三家を選ぶ前に通常の手順でMystery Giftへ入れません。本プラグインは早期解放や「はじめから」にまたがる注入の保持には対応しません。

## 色違いとの遭遇後に投球する

1. **注入前に**「遭遇後の捕獲検索を事前に読み込む」を有効にします。画面では初期状態で有効です。捕獲ボールはモンスターボール（既定）またはハイパーボールを選べます。既存の0.6.0のRAM注入へ戦闘中に機能を追加することはできません。プラグインの更新後は、新たな注入が必要です。
2. 生成が終わり戦闘に入ったら、自分でボールを選び、最後の**Use（つかう）**確認で止めます。Rを押しながらSELECTを1回押し、両方を離してください。
3. 下段は**8が検索中、9が投球までのカウントダウン**です。指定時点で**Aを1回**入力します。捕獲検索は隣り合う成功候補をまとめ、連続区間の中心を優先します。3候補が連続する場合は中央を選びます。**緑は現在の消費数とA入力時点の偶奇が一致、黄は不一致**を表します。偶奇は表示だけで、手動で調整できます。この比較には捕獲Offsetを反映しています。ホウオウの生成には↑を使用しますが、捕獲はすべてAです。PCのインストールセッションが終わってもゲーム機上で動作し続けるため、Mystery Giftへの移動やseedの再設定は不要です。
4. **R+SELECT**をもう一度押すとキャンセルし、Eを表示します。E、または1回の投球後のCから、再び検索を開始できます。押し続けても繰り返し有効にはなりません。キャンセル後に自動投球は行いません。
5. 表示された対象は固定されます。入力時点の通過、コールバックの変更、RNG確認の失敗では、赤いDを約1秒表示してから再検索します。過ぎた対象に対する遅れた入力は行いません。投球後のCは入力を送ったことを表すため、実際に捕獲できたかはゲームで確認してください。

捕獲モデルは、ユーザー提供のv24 / v27gの検証ロジックに従います。モンスターボールのしきい値は**16643**、ハイパーボールは**19784**で、Offset範囲内のすべての開始位置に対し4回とも厳密な判定を通る必要があります。現在はこの2種類を区別し、HP・状態異常の絞り込みはありません。通常の捕獲可能な野生戦闘が対象です。サファリゾーン、トレーナー戦、捕獲不能な相手は、このメニュー操作の対象外です。

**捕獲Offsetと生成Offsetは独立**しており、どちらも単位はRNG消費数です。捕獲Offsetは、実際にAを受け取るコールバックのseedから、最初の揺れ判定のRandom直前までを数えます。コールバック前の1回のRFU消費は、常駐コードが別途加算します。初期値の**241**は校正前の参考値です。上限を空欄にすると下限と同じ値になり、上限を指定すると範囲全体で成功する候補を要求します。v24の242～245は以前のSysBot経路での実測値であり、本プラグインで検証済みのOffsetを意味しません。

元のPythonモデルはユーザーによる実機検証済みです。**本プラグインの投球開始位置、1回入力のタイミング、捕獲表示、Offsetは、まだ実機での受け入れ確認が必要です。**まず色違い以外を許可した通常の試行で確認し、色違いの試行では検証済みの捕獲Offsetを固定してください。出典と消費位置の定義は[捕獲モデル（中国語）](docs/CAPTURE_MODEL.md)を参照してください。

## Offset

単位は**RNG消費数**であり、映像のフレーム数や秒数ではありません。プリセットと手動入力は追加の先行消費数です。基礎値はミュウツーが1、三鳥・その他の固定対象が2、野生が1です。フリーザーのプリセットは3で、先行量の合計は5になります。ミュウツーのプリセットは2で、合計は3です。

対象・場所の選択肢にプリセットを表示します。手動Offsetが空欄ならプリセットを使用し、**0**を入力すると明示的に上書きします。入力可能な範囲は0..65533です。選択したゲームに対応する列を使用します。**野生の不明な値は256を初期値にします。**

| 野生の場所 | ファイアレッド | リーフグリーン |
| --- | ---: | ---: |
| 1・2・3・4・5・6・11・18・24・25ばんどうろ | 256 | 256（不明時の初期値） |
| トキワのもり | 250 | 256（不明時の初期値） |
| オツキミやま・ディグダのあな | 263 | 256（不明時の初期値） |
| むじんはつでんしょ | 256（不明時の初期値） | 263 |
| ポケモンタワー3F | 259 | 256（不明時の初期値） |
| サファリゾーン | 256 | 257 |
| ポケモンやしき | 257 | 257 |
| チャンピオンロード・いてだきのどうくつ・ハナダのどうくつ | 263 | 256（不明時の初期値） |
| ともしびやま | 256 | 256 |
| その他・参考データなし | 256 | 256 |

固定対象の参考値は、御三家・コイキング・カビゴン・トゲピー・徘徊初期化・化石・ゲームコーナーが3、イーブイが4、格闘道場が6、スリーパーが86、デオキシスが501、ルギアが277、ホウオウが379です。マルマイン、ラプラス、任意の対象には参考値がなく、0を維持しています。

参考表はユーザー提供です。すべての発動方法、言語、場面で実測したものではなく、参考の映像フレーム数を実測済みのRNG消費数として確認したものでもありません。実際の結果が元の対象より3消費遅ければ、現在の追加Offsetに3を加えます。3消費早ければ3を引きます。2つ目のツールで補正の候補を確認できます。複数回の実機テストで確かめてください。

検索範囲は両端を含み、最大9999999です。固定対象の位置は最初のPID抽選前、野生の位置は遭遇スロット抽選前を表し、その後にレベル・性格・PIDの再抽選が続きます。初期化済みの徘徊個体との再遭遇では、新しい個体は生成されません。固定PIDの交換や通常の孵化は、このモデルの対象外です。

## 野生ポケモンと個体値の絞り込み

**ゲーム → 野生 → 遭遇方法 → 正確な場所・階 → 野生ポケモン**の順に選択します。ポケモンの種類は初期状態で指定なしです。データにはファイアレッド・リーフグリーンの132組の遭遇テーブルを収録し、草むら・洞窟、水上、いわくだき、3種類のつりざおを分けています。階、サファリのエリア、バージョン限定種も区別します。例えばトキワのもりでピカチュウを選ぶと、そのテーブルのピカチュウのスロットだけを受け付けます。発電所のエレブーはファイアレッド限定です。

ポケモンのリストには収録した野生種すべてを表示し、他の項目に合わせて動的に絞り込みません。インストール前にゲーム、場所、遭遇方法を確認してください。存在しない組み合わせはエラーになります。種類を絞り込む場合は「その他・不明」や複数階をまとめた場所を使わず、正確な階・エリアを指定してください。種類を指定しなければ、従来の広い場所区分とOffsetを使用できます。へんげのどうくつのイベントテーブルは実際のゲーム状態と一致させる必要があります。アンノーンは独立した分類・部屋モデルを使用し、通常の性格再抽選モデルは適用できません。ゲーム機の現在地は読み取らず、徘徊個体が通常のあまいかおり遭遇を置き換える場合にも対応しません。

**6項目すべての個体値の下限・上限が、ゲーム機上の検索に反映されます。**種類、性格、色違い条件と組み合わせられます。入力順はHP・こうげき・ぼうぎょ・とくこう・とくぼう・すばやさです。例えば、とくこう・すばやさを25以上にするなら、下限を`0,0,0,25,0,25`、上限を`31,31,31,31,31,31`にします。すばやさをちょうど0にする場合は、その下限・上限を両方0にしてください。条件が厳しいほど、範囲内に候補がなくなる可能性があります。ポケモンのデータを書き換えたり、狙いどおりの結果を保証したりする機能ではありません。最初は色違い以外も許可し、個体値を指定せず、種類とOffsetを確認してから条件を増やしてください。

## ゲーム画面の表示と操作

通常は上段に現在のseedを16進数8桁で、下段に状態記号と10進数7桁を表示します。

| 下段 | 意味 |
| --- | --- |
| Axxxxxxx | 生成対象の検索位置 |
| Bxxxxxxx | 入力時点までの残り消費数。黄は偶奇不一致、緑は偶奇一致かつコールバックが利用可能 |
| 8xxxxxxx | 捕獲対象の検索位置 |
| 9xxxxxxx | 投球のA入力時点までの残り消費数。黄は偶奇不一致、緑は偶奇一致かつコールバックが利用可能 |
| C0000001 / C0000000 | 今回のコールバック待ち・1回の入力を送信済み |
| D00000xx | 入力時点の通過・入力失敗の理由。赤で約1秒表示した後、有効な範囲内で再検索 |
| E0000000 / F0000000 | 範囲終了（捕獲ではキャンセルも含む）・消費数の追跡が無効 |

Bまたは9になった対象は保持し、色が変わっても先に別の対象へ切り替えません。生成検索は到達可能な偶奇を使います。捕獲検索は成功区間の中心を優先し、偶奇の色表示だけでは中心を変更しません。偶奇は対応するOffsetを反映した入力時点と比較します。緑色だけではOffsetの校正が済んだとは判断できません。実際に入力時点を逃した場合はDを表示してから再検索し、期限切れの対象には入力しません。入力後に自動で検索を再開することもありません。Cは入力の送信を表すため、実際の動作はゲームで確認してください。捕獲はR+SELECTで再び手動で有効にできます。

| 押し続けるボタン | 上段 | 下段 |
| --- | --- | --- |
| L | 初期seed | 絶対消費数 |
| R | HP・こうげき・ぼうぎょ・すばやさ。各10進数2桁 | とくこう・とくぼう・めざめるパワーのタイプ番号・威力。各10進数2桁 |
| L+R | 手持ちの最後のポケモンの完全なPID（16進数） | 手持ちの位置1..6 |

例えば全個体値31、めざめるパワーがあく・威力70なら、Rで**31313131 / 31311670**と表示します。タイプ番号01..16は、かくとう・ひこう・どく・じめん・いわ・むし・ゴースト・はがね・ほのお・みず・くさ・でんき・エスパー・こおり・ドラゴン・あくの順です。

Rはセーブ時のコピーではなく、現在の手持ちの最後のポケモンを読み取ります。手持ちなし・異常データ・チェックサム不一致はFFFFFFFF / FFFFFFFF、L+Rで手持ちなしの場合はFFFFFFFF / 00000000です。確認中もカウントダウンや時刻指定入力は止まりません。隠れていたDの表示時間は、ボタンを離してから進みます。ZL・ZRを別の入力として識別する機能はありません。

生成段階では、フィールド用の設定はフィールドで表示します。あまいかおり・釣り・アンノーン・御三家の設定はメニューでも表示・動作しますが、いずれも最初にフィールドへ戻って実際のseedを確定する必要があります。メニュー中でも入力時点に達すると入力するため、正しい決定位置で待機してください。生成段階では、認識済みの戦闘コールバックへ入力しません。手動で捕獲を有効にすると、戦闘・バッグのコールバックと捕獲表示を使用できます。

Dの理由コードは、04がコールバック利用不可・変更、09が入力時点の通過、10がメインループ処理中、11がコールバック前のRNGが想定する1回の無線消費と不一致、12が入力コールバックの期限切れです。フィールド用の設定でおしえテレビ中に対象を通過した場合、フィールドに戻ってから通知を表示し、その表示時間を数えます。

## PIDを手入力して実際の消費数を逆算

2つ目のツールに、Lで表示した初期seedとL+Rで表示した実際のPIDを、どちらも16進数で**手入力**します。試行と同じ分類、対象、方式、範囲を選択してください。元の対象消費数と使用したOffsetを追加すると、実際のずれと新しいOffsetの候補を確認できます。

例えば初期seedが**C76F**、PIDが**4762A09B**、対象がフリーザーなら、実際の位置は**3354消費**です。元の対象が3351、追加Offsetが3なら、差は+3で、推奨される追加Offsetは6になります。

野生のPID再抽選では、複数の遭遇開始位置が同じPIDに対応する場合があります。ツールはすべての候補を表示するので、実際の範囲を狭めるか、Rで表示した個体値と照合してください。レポートの個体値・めざめるパワーは**選択した方式による予測値**です。逆算だけで入力の成功や捕獲の由来を証明することはできません。

## 開発と配布

ソース：[axechaso/frlg-rng-assist](https://github.com/axechaso/frlg-rng-assist)。独立して開発・配布しています。pushするとGitHub Actionsが動作し、テスト用パッケージを生成します。開発用ホストはv0.39.1 / 4780dcaeac52479e6212483009f64f348581d7ccに固定し、Python 3.13・GCC 15.2.1を使用しています。

```powershell
python -m pip install -r requirements-dev.txt
$env:POKELDN_SOURCE = 'D:\path\to\pokeldn-v0.39.1'
python -m ruff check .
python -m pytest -q
python scripts/build_guest.py --check
python D:\path\to\pokeldn-v0.39.1\scripts\pack_plugin.py . -o dist\frlg-rng-assist-0.7.3.pokeplugin
```

再ビルドする場合は、ARM_TOOLCHAINに末尾の区切り文字を含むARMツールのディレクトリを設定し、scripts/build_guest.pyを実行します。常駐領域は2200バイトのままです。捕獲を読み込まない場合は2152バイト、捕獲対応の固定・野生・アンノーンはそれぞれ2068・2188・2200バイトです。インストール時にモデルに合う完全な1種類を選択し、他の常駐フックとは併用できません。初期化後はfirst・初期ジャンプ引数を保持していたRAMの3ワードを一時状態として再利用し、予約領域は拡大しません。種類は引き続き100ビットのスロットマスクで表現します。RNG、ポケモン、セーブ、ROMのデータには書き込みません。ゲームの復号アクセサにはスタック上のコピーだけを渡します。

静的な遭遇データを更新する場合は、`python scripts/import_wild_data.py --decomp PATH --pokefinder PATH`を実行します。登録済みデータには出典のcommitを記録しています。利用者がこれらの開発用依存関係をインストールする必要はありません。種類名・性格名の翻訳元とライセンスはNOTICEを参照してください。
