# FRLG RNG Assist 0.3.9

PokeLDN 的第三方插件：设置 RNG advances 范围与条件，注入临时掌机程序，显示 seed / 倒计时，到点自动按一次 A。**这是待实机验证的测试版。软件模拟通过不代表掌机时序已经通过。**

首轮先按 [实机测试步骤](docs/HARDWARE_TEST_ZH.md) 测试，不限制性格或 IV，并打开「允许非闪光」。

**0.3.9 修正「一直绿色，目标 3351 却生成在 3354」的时序偏移。**无线路径中，脚本等待完成后要到下一轮才继续执行，期间每轮还有 RFU 和 VBlank 的 RNG 推进。三鸟从按 A 到生成前的总提前量由 2 改为 **5 advances**，超梦由 1 改为 **3 advances**；颜色和候选奇偶筛选使用修正后的按 A 时机。用初始 seed `C76F` 复现旧版目标 `1D138B25`、实际 `4762A09B`；修正后的软件模型回到目标 PID。修正版仍待实机确认，绿色只表示按 A 时机的奇偶与当前条件一致。

新增 **「额外 Offset（advances）」**：这次急冻鸟填 `3`，表示比 0.3.7 / 0.3.8 再提前 3 advances。插件原有基础提前量为三鸟 2、超梦 1；三鸟填 3 后合计提前 5，**这里不用填 5**。留空自动使用三鸟 3、超梦 2；填 `0` 可恢复旧版时机，允许 `0..253`。范围仍针对最终生成目标，倒计时和奇偶颜色按补偿后的按 A 时机计算，安装报告保存额外、基础和合计提前量。若多次实测都稳定晚 1 advance，可将 Offset 加 1；稳定早 1 则减 1，再重新启动游戏并注入。

**0.3.8 新增按住 L+R 查看队尾 PID：**上排白色显示完整 8 位十六进制 PID，下排显示队尾位置 1–6。松开后恢复；单独按 L 仍查看初始 seed。读取当前队伍，无需先保存，查看时倒计时和自动 A 继续运行。

**三鸟到点直接按一次 A，无需按住 B，也不检测相邻、朝向、移动、目标对象或脚本状态。**你提前走到要按 A 的位置，松开按键等待即可。旧版的持续按 B 门槛不符合这个流程，已在 0.3.3 移除；此前的初始 seed 地址修复和时序错误码保留，详见 [修改记录](CHANGELOG.md)。

0.3.7 修正了按键回调前一次正常无线 RNG 推进被误报 D11 的错误；当时没有修正后续脚本等待期间的推进，生成时序在 0.3.9 一并修正。缺少或多出回调前推进仍会取消本次 A。

B 倒计时与自动 A 时机奇偶不一致时为黄色，一致且当前回调可触发时为绿色；颜色变化不提前丢弃目标。实际错过或本次按键失败后，红色 D 原因码在地图保留约一秒，再按同一初始 seed、原范围和原条件搜索更晚的候选。教学电视中错过，会等回到地图后显示这段提示。发送一次 A 后结束；范围耗尽显示 E，计数失效显示 F。

## 安装与支持范围

- 使用 PokeLDN **v0.39.1 / 插件 API 1.11**。开发检查固定在该版本。
- 安装 `frlg-rng-assist-0.3.9.pokeplugin`：Plugins → Add a plugin；已有旧版时用插件卡片的文件更新入口。
- Games → FireRed & LeafGreen → **RNG：搜索与到点自动 A**。
- 本版只接受 Switch 火红 / 叶绿英文、法文 **rev 0A**：BPRE、BPGE、BPRF、BPGF。原版 GBA 卡带的 rev 0/1、其他语言或改版 ROM 不在本版范围内。
- ESP32 的 Wireless 固件版本与插件 API 是两回事；无需为了这个插件更换已经能正常运行 PokeLDN 的 Wireless 1.8.0。
- 无需安装 Python 或 ARM 编译器。包内附有掌机源码、生成脚本和预编译资源。

## 工作逻辑

1. PC 导出范围、目标、闪光 / 性格 / IV 条件，使用 PokeLDN 的公开 Mystery Gift 工具传输。未完整传完、校验失败或已有 resident hook 时不启用。
2. 离开 Mystery Gift 回到标题。标题按 START 后，游戏用计时器重新播种；插件读取游戏保留的**这个实际初始 seed**。Mystery Gift 会话中的 seed 不用于地图计数。
3. 以实际初始 seed 为 advance 0，读取当前 RNG 状态并算出绝对 advances。因此进入地图时一般已经不是 0。PC 配置的范围也使用这个起点。
4. 掌机在正常地图运行期间分批搜索自然 Method 1 结果，使用当前存档的 TID/SID，并读取实际 RNG 推进量。A 阶段完成搜索和初始候选确认；进入 B 倒计时后固定目标，走路等额外消耗只反映到实际计数中。
5. 找到候选后显示到自动 A 时机的剩余 advances。自动 A 时机已经扣除基础提前量和配置的额外 Offset；默认合计为超梦 **3 advances** / 三鸟 **5 advances**。它与当前 advances 奇偶不一致时显示黄色，一致且回调可触发时显示绿色。颜色不改变原目标，也不保证之后的推进量固定。三鸟到点直接注入 A，站位由你负责；超梦沿用指定脚本等待配置，未进入等待阶段也显示黄色。忙帧、移动或其他额外消耗仍可能影响按键后的实际生成时序，最终以实际 PID 为准。
6. 实际越过目标、遇到忙帧、按键回调过期或当次状态不符时，红色 D 原因在地图保留 60 个显示帧（约一秒），再搜索更晚的候选。菜单 / 教学电视不消耗这段提示时间；提示期间仍跟踪实际 RNG，但不搜索或发送 A，结束后从实际位置续搜。不会补按旧目标、重置起点或扩大范围。
7. 每次安装最多注入一次 A，发送后不再续搜。范围耗尽或初始 seed 时段失效时结束。插件不会改 RNG、PID、IV 或存档内容。

范围包含端点，最大 `9999999`，针对**生成 PID 前**的 RNG 状态。倒计时针对**按 A**的时机，包含上述偏移；不是屏幕帧数或秒数。软重启或关闭游戏会清除临时程序；正常退出 Mystery Gift 到标题再继续游戏可以保留。

## 掌机显示

右上角上排显示 8 位十六进制当前 seed；下排是状态字母加 7 位十进制数字。

| 下排 | 含义 |
|---|---|
| `Axxxxxxx` | 搜索 / 确认中，包括错过后的续搜；数字是搜索位置或候选的绝对 advance |
| `Bxxxxxxx` | 固定目标到按 A 的剩余 advances；奇偶不一致为黄色，一致且当前可触发为绿色，不检查三鸟站位 |
| `C0000001` | 已排定 A，尚未执行按键回调 |
| `C0000000` | 已注入一次 A；是否实际进入战斗仍需观察 |
| `D00000xx` | 红色显示本候选错过 / 按键失败的原因，在地图保留约一秒后续搜 |
| `E0000000` | 范围内没有剩余可用候选；不按 A |
| `F0000000` | 初始 seed 改变、回退或超出计数范围；不按 A |

**按住 L**：上排改为实际初始 seed，下排改为当前绝对 advances。松开恢复；L 不重置计数。

**同时按住 L+R**：上排白色显示当前队尾宝可梦的完整 8 位十六进制 PID；下排 `00000001`–`00000006` 表示队尾位置。包含前导零；`00000000` 也可能是有效 PID。松开 R、继续按 L 时返回初始 seed 视图，两键都松开时恢复正常显示。单独按 R 不切换插件显示。

队伍为空或数量异常时，上排 `FFFFFFFF`、下排 `00000000` 表示没有可显示的队尾 PID。读取的是当前队伍，重排或队伍数量改变后随即更新，无需先保存。新捕获宝可梦送进电脑时，队尾仍是原有队员；要查看它，请先放进队伍。

查看 seed / PID 时不会暂停实际计数、搜索或自动 A；隐藏的 D 提示时间会保留到松开相应按键后再计。先把游戏 **OPTIONS → BUTTON MODE 设为 L/R 并保存**，避免 L/R 打开帮助页。本插件不单独读取 ZL/ZR。菜单和战斗中不绘制这个显示。

| D 原因码 | 条件 |
|---|---|
| `03` | 超梦脚本未处于指定按键等待阶段 |
| `04` | 不在正常地图回调 |
| `05` | 超梦的当前交互对象不符 |
| `09` | 已越过按 A 的 advance |
| `10` | 目标时刻主循环仍忙 |
| `11` | 按键回调前 RNG 不符合预期的一次正常推进 |
| `12` | 排定的按键回调过期 |

例如 `D0000011` 是按键回调前的 RNG 状态不符，提示结束后会重新选取未来候选。0.3.7 已计入无线通信路径正常的一次推进，旧版会将它误报为 D11。正常地图或主循环尚未恢复时，D 会保留到能够续搜；续搜可能很快找到候选，D 后可以直接出现新的 B。0.3.3 不再产生旧版的三鸟原因码 `01`、`02`、`06`、`07`、`08`。

教学电视可能一次推进很多 advances，实际超过旧目标后无法回到该时机；返回地图会先显示红色 `D0000009` 再续搜。尚未超过时保留旧目标。奇偶不一致只改变 B 的颜色，不直接触发换目标。

## 其他工具

- **核对捕获结果**：目标放在队伍中，游戏内保存，再进 Mystery Gift 读取最后保存的队伍；也可导入 `.pk3` / `.ek3` / 608 字节队伍 dump。可关联安装报告继承条件，并输入按 L 记录的初始 seed 核对生成 advance 是否在范围内。仅核对所选宝可梦记录，不自动证明实际按键时序或捕获来源。
- **离线目标搜索**：公开 API 的 Method 1/2/4 预测，筛选闪光、性格、PID 和六项 IV。
- **PID / IV 反推**：恢复过去可能的生成状态，可比较同一时段内的距离；不把反推结果当实时读数。

IV 顺序统一为 HP、攻击、防御、特攻、特防、速度。首轮实机先保留全范围 `0..31`；IV 筛选不作为本轮验收条件。

报告与采集文件保存到 PokeLDN 的 **FRLG RNG Assist** 资料库。显式指定文件名时不覆盖已有文件。安装失败不会生成“安装成功”报告。

## 当前限制

一次只安装本插件；开始前重新启动游戏，清除其他 boosts / resident hooks。代码使用上游记录的未使用 newlib 区和 EWRAM 顶部区域，合计最多 2200 字节；已知 revision / 函数特征不符时拒绝。它不应与其他驻留扩展叠加使用。

目前自动 A 仅覆盖超梦和三鸟的这两类等待方式。其他静态、野生、蛋或礼物遭遇没有可用的自动 A 配置。范围过窄、赶路耗尽候选、额外 RNG 消耗或过迟到达等待点都可能失败。先验证「出现显示 → 倒计时 → 自动开战」，再验证闪光和筛选结果。

## 开发与检查

Python 3.13，独立 PokeLDN v0.39.1 源码目录（含其依赖），开发依赖见 `requirements-dev.txt`：

```powershell
python -m pip install -r requirements-dev.txt
$env:POKELDN_SOURCE = 'D:\path\to\pokeldn-v0.39.1'
python -m pytest -q
python -m ruff check .
```

重新编译掌机程序需要 GNU Arm Embedded GCC，并将工具目录设为 `ARM_TOOLCHAIN`（以目录分隔符结尾），或把工具加入 PATH：

```powershell
python scripts/build_guest.py
python -m pytest -q
```

`scripts/build_guest.py --check` 在相同 GCC 版本下核对已提交资源。不同编译器生成的地址和字节可以不同，重新生成后必须重新跑模拟测试。交付资源使用 GCC 15.2.1。

用 PokeLDN 自带的打包器，不向其仓库添加插件：

```powershell
python D:\path\to\pokeldn-v0.39.1\scripts\pack_plugin.py . -o dist\frlg-rng-assist-0.3.9.pokeplugin
```

验证范围和已知未测项见 [验证记录](docs/VALIDATION.md)。本项目独立开发，目前交付本地测试包，没有配置远程发布地址。
