# FRLG RNG Assist 0.7.1

PokeLDN 独立第三方插件。设置 RNG advances 范围和条件，掌机显示 seed / 倒计时，到点触发一次按键。你自行到最后决定点；**凤王按 ↑，其余目标按 A**，无需按住 B。

这是实机测试版。软件与离线宿主检查不能代替实机时序验收，见 [验证记录](docs/VALIDATION.md) 和 [测试步骤](docs/HARDWARE_TEST_ZH.md)。

## 安装与界面

使用 PokeLDN v0.39.1 / API 1.11，Plugins → Add a plugin，选择 **frlg-rng-assist-0.7.1.pokeplugin**。已有版本可在插件卡片更新。支持 Switch 英文 / 法文 rev 0A：BPRE、BPGE、BPRF、BPGF，Wireless 1.8.0 可继续使用。包内有预编译代码，用户不需要 Python 或 ARM 编译器。

工具名称、说明、分类、地点、物种、性格和输出支持**中文 / 日本語 / English**，跟随 PokeLDN 的 App language。更改宿主语言后重启 PokeLDN 重新载入插件；其他界面语言回退到英文。中文 / 日文宿主需要对应的 PokeLDN 语言包。这是界面翻译，游戏支持范围仍为上述英文 / 法文构建。安装卡片的简介为三语共用文本。

Games → FireRed & LeafGreen 下只保留两个工具：

1. **RNG：搜索与到点按键**：注入筛选条件、搜索并倒计时，到点发一次按键。
2. **RNG：PID 反查实际命中**：用户手动填写本轮初始 seed 和实际 PID，反查命中 advance；无需连接掌机或填写 IV。

目标采用分类选择：御三家、化石、礼物 / 购买、游戏厅、普通定点、传说定点、活动定点、游走初始化、野生、未知图腾及其他定点。定点 / 礼物只提供 **Method 1 / 4**；野生提供 **H1 / H2 / H4**。野生再选择甜香、钓竿或碎岩及地点，未知图腾另外选择房间。

## 一次尝试

1. 在目标附近保存，OPTIONS → BUTTON MODE 设为 **L/R**，重新启动并清除其他 boosts。
2. 在 PC 选择游戏、类别、目标或野生地点及范围。首测允许非闪光，性格 / IV 不限。目标和地点旁显示预设 Offset；手动 Offset 留空即自动采用预设。
3. PC 点 Start，掌机 Mystery Gift → Wonder Cards → Friend → POKELDN，等待安装回执 **0x524E4703**。
4. 正常退出到标题，再继续游戏。以标题实际初始 seed 为 advance 0；进入地图时计数通常已经大于 0。
5. 自行停在最后决定点，松开按键等待。三鸟停在面前；超梦停在对话末的按键等待；甜香停在队伍菜单该选项；钓鱼自行完成前面轮次；凤王停在触发格南边相邻一格并朝上。
6. 观察是否实际触发。捕获后用 R 查看实际 IV，L+R 查看队尾 PID，再用第二个工具手动反查。

插件不检测站位、朝向、对象或脚本等待，也不自动走路、导航菜单或反复钓鱼。生成只发一次按键；预载捕获后，可在本场战斗继续启用投球。软重启 / 关闭游戏清除注入，下一轮需重新安装。新存档选御三家前正常流程无法进入 Mystery Gift，本插件不提供提前解锁或跨新游戏保留。

## 出闪后投球

1. **注入之前**勾选「预载出闪后的捕获搜索」（界面默认勾选）。已有 0.6.0 RAM 注入不能在战斗中补装，更新插件后需重新注入。
2. 完成生成、进入战斗后，自己选球，停在最后一次 **使用 / Use** 确认处。此时不按 A，按住 R 并点一次 SELECT，然后松开两键。
3. 下排 **8** 搜索、**9** 投球倒计时；到点自动按一次 **A**。凤王的生成仍用 ↑，投球统一用 A。PC 安装会话结束后此功能仍在掌机运行，不需要返回 Mystery Gift 或重新播种。
4. 再按 **R＋SELECT** 可取消，显示 E；在 E 或一次投球后的 C 状态可重新启动搜索。只保持按键不重复启用。取消后不会自动投球。
5. 目标一经显示就锁定。错过、回调改变或 RNG 检查失败先显示红色 D，约一秒后重新搜索；不会补按旧目标。投球后 C 表示已发送输入，实际捕获结果看游戏。

捕获模型使用用户提供的 v24 / v27g 验证逻辑：**阈值固定 16643**，覆盖偏移带内每个可能起点的四次严格判定。没有 HP、状态、球倍率筛选项。适用于普通可捕获野生战斗；狩猎地带、训练家和不可捕获目标不适用这套菜单流程。

**捕获 Offset 与生成 Offset 完全独立**，单位均为 RNG advances。捕获 Offset 从实际 A 回调的 seed 数到第一次摇球 Random 前；掌机端另外计入回调前的一次 RFU 推进。默认 **241** 只是待校准的参考起点，上限留空等于下限；填写上限可要求整个偏移带全部成功。v24 的 242～245 是旧 SysBot 路径的实测范围，不能直接标为本插件已验证。

原 Python 工具的模型已有用户实机验证，**本插件的投球入口、单次按键时序、捕获显示和 Offset 尚待实机验收**。先用允许非闪光的普通轮验证，再在闪光轮保持已验证的捕获 Offset。模型出处和坐标定义见 [捕获模型](docs/CAPTURE_MODEL.md)。

## Offset

单位为 **RNG advances**，不是画面帧或秒。界面预设与手动值都是额外提前量：超梦基础 1，三鸟 / 其他定点基础 2，野生基础 1。急冻鸟预设 3，合计提前 5；超梦预设 2，合计提前 3。

预设直接显示在目标 / 地点选项后；手动 Offset 留空自动使用，填写 **0** 会明确覆盖预设。可填范围 0..65533。切换游戏后按对应列取值，**未知野生值默认 256**。

| 1、2、3、4、5、6、11、18、24、25 号道路 | 256 | 256（未知默认） |
| 常青森林 | 250 | 256（未知默认） |
| 月见山、地鼠洞穴 | 263 | 256（未知默认） |
| 无人发电厂 | 256（未知默认） | 263 |
| 宝可梦塔 3F | 259 | 256（未知默认） |
| 狩猎地带 | 256 | 257 |
| 宝可梦屋 | 257 | 257 |
| 冠军之路、冻瀑洞窟、华蓝洞窟 | 263 | 256（未知默认） |
| 灯火山 | 256 | 256 |

定点参考包括御三家 / 鲤鱼王 / 卡比兽 / 波克比 / 游走初始化 / 化石 / 游戏厅 3、伊布 4、道场 6、引梦貘人 86、代欧奇希斯 501、洛奇亚 277、凤王 379。顽皮雷弹、拉普拉斯及自定目标暂无参考，保留 0。

参考表由用户提供，尚未在每种触发方式、语言和场景实测，也没有把参考画面帧数当成已经测得的 advances。若实际命中比原目标晚 3 advances，应将当前额外 Offset 加 3；早 3 则减 3。第二个工具可给出这一修正建议，需多次实测确认。

搜索范围含端点，最大 9999999。定点索引为首次 PID 抽取前；野生索引为遭遇槽位抽取前，后续包含等级、性格和 PID 重抽。已初始化游走宝可梦的再次遭遇不属于重新生成。固定 PID 交换和普通遗传蛋不属于这里的随机模型。

## 野生物种与 IV 筛选

选择**游戏 → 野生 → 遭遇方式 → 具体地点 / 楼层 → 野生宝可梦**。物种默认为「不限」，保留原有流程。数据包含 132 组火红 / 叶绿遭遇表，区分草地 / 洞窟、水面、碎岩以及三种钓竿；楼层、狩猎区和版本限定种分别计算。例：常青森林选皮卡丘，掌机只接受该表的皮卡丘槽位；发电厂电击兽只属于火红。

物种下拉是所有已收录野生物种的共用列表，不随其他字段动态缩短。选择后在安装前核对游戏、地点和遭遇方式；不存在的组合会报错。筛物种时不能使用「其他 / 未知」或合并楼层，需选择具体楼层 / 区域。不筛物种时仍可使用原来的粗略地点和 Offset。变幻洞窟的事件表需与实际游戏状态一致；未知图腾使用独立类别及房间，不能套普通性格重抽模型。该筛选不读取掌机当前地图，也不处理游走宝可梦替代普通甜香遭遇的情况。

**六项 IV 的上下限已在掌机搜索中实际生效**，可与物种、性格和闪光同时筛选。输入顺序为 HP、攻击、防御、特攻、特防、速度；例如特攻至少 25、速度至少 25，可将下限设为 `0,0,0,25,0,25`，上限保持 `31,31,31,31,31,31`。精确 0 速度则将速度上下限都填 0。条件越严，范围内越可能没有结果；它不会修改宝可梦数据或保证命中。首测先允许非闪光、IV 不限，核对物种及 Offset，再逐步加条件。

## 掌机显示与按键

普通显示上排为 8 位十六进制当前 seed，下排为状态字母和 7 位十进制数。

| 下排 | 含义 |
| --- | --- |
| Axxxxxxx | 搜索位置 |
| Bxxxxxxx | 到按键时机的剩余 advances；黄色奇偶不同，绿色一致且回调可用 |
| C0000001 / C0000000 | 等待本轮回调 / 已发送一次按键 |
| D00000xx | 错过或按键失败原因，红色显示约 1 秒后在原范围续搜 |
| E0000000 / F0000000 | 范围耗尽 / 计数失效，本轮结束 |

一旦出现 B 就保留目标，颜色变化不提前换目标。实际错过才显示 D 并续搜，不补按过期目标；已发按键不再续搜。C 表示输入已发出，是否实际触发须观察游戏。

| 按键 | 上排 | 下排 |
| --- | --- | --- |
| L | 初始 seed | 绝对 advances |
| R | HP、攻击、防御、速度，各两位十进制 | 特攻、特防、觉醒属性编号、威力，各两位十进制 |
| L+R | 队尾完整 PID（十六进制） | 队尾位置 1..6 |

例如全 31 IV、觉醒恶 70，R 显示 **31313131 / 31311670**。属性编号 01..16 依次为：格斗、飞行、毒、地面、岩石、虫、幽灵、钢、火、水、草、电、超能、冰、龙、恶。

R 的数据来自当前队尾，而不是存档副本。空队伍 / 异常 / 校验失败显示 FFFFFFFF / FFFFFFFF；L+R 空队伍为 FFFFFFFF / 00000000。查看不暂停倒计时或到点按键，隐藏的 D 提示等松开后继续显示。本插件不单独识别 ZL / ZR。

生成阶段：地图配置在地图显示；甜香、钓鱼、未知图腾及御三家配置也在菜单显示和运行，均先回地图建立实际 seed。菜单中到点会尝试按键，请自行停在正确决定点。生成阶段不向已识别的战斗回调发送；手动启用捕获后支持战斗 / 背包回调，并显示捕获状态。

D 原因码：04 回调不可用或改变；09 越过按键时机；10 主循环忙；11 回调前 RNG 不符合预期的一次无线推进；12 按键回调过期。地图配置在教学电视里错过时，回到地图才显示提示并计时。

## 手动 PID 反查

在第二个工具中**手动填写** L 显示的初始 seed、L+R 显示的实际 PID，两者均为十六进制。选择与本轮一致的类别、目标、方式和范围。可额外填写原目标 advance 和使用过的 Offset，查看实际误差和建议新 Offset。

例如初始 seed **C76F**、PID **4762A09B**、目标急冻鸟，对应实际 advance **3354**。原目标 3351、原额外 Offset 3 时，差值 +3，建议额外 Offset 6。

野生的 PID 重抽可能导致多个遭遇起点共享 PID，工具列出全部候选；缩小实际范围或对照 R 的 IV 再判断。报告里的 IV / 觉醒力量是所选生成方式的**预测值**。反查结果不单独证明输入成功，也不证明捕获来源。

## 开发与分发

源码：[axechaso/frlg-rng-assist](https://github.com/axechaso/frlg-rng-assist)。独立开发和分发，推送会运行 GitHub Actions 并生成测试包。开发宿主固定 v0.39.1 / 4780dcaeac52479e6212483009f64f348581d7cc；Python 3.13、GCC 15.2.1。

    python -m pip install -r requirements-dev.txt
    $env:POKELDN_SOURCE = 'D:\path\to\pokeldn-v0.39.1'
    python -m ruff check .
    python -m pytest -q
    python scripts/build_guest.py --check
    python D:\path\to\pokeldn-v0.39.1\scripts\pack_plugin.py . -o dist\frlg-rng-assist-0.7.1.pokeplugin

重新编译时设置 ARM_TOOLCHAIN 为带末尾分隔符的 ARM 工具目录，运行 scripts/build_guest.py。驻留区仍为 2200 字节：未预载捕获为 2156；预载后的定点 / 野生 / 未知图腾分别为 2032 / 2180 / 2196。安装时按模型选取一个完整版本；不能叠加其他 resident hooks。初始化后复用 first / 初始跳转参数三个 RAM 字作为临时状态，不扩大保留区。物种仍编码为 100 位槽位掩码。插件不写 RNG、宝可梦、存档或 ROM；游戏的解密访问器只接收栈副本。

更新静态遭遇数据时，运行 `python scripts/import_wild_data.py --decomp PATH --pokefinder PATH`。已提交的数据记录来源 commit，用户无需安装这些开发依赖。物种 / 性格译名来源和许可证见 NOTICE。
