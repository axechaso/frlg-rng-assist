# 捕获模型与输入坐标（0.7.1）

用户提供的 `FRLGSwitchSeedFarmer` 同目录包含：

- `frlg_capture_engine_v24.py`，SHA-256 `55b69f64e5027f032baee5293074c4a174fcdf5dad917ad4ff68ea8a5c50dfc5`。
- `frlg_easycon_capture_calibrator_v27g.py`，SHA-256 `cf04bad23ce7663cc818a428637a92a928a3d59aa8748ff2a8460046c1d52842`。

v24 的 `check_capture_band` 与 v27g 的 `verify_band` 使用相同的偏移带判定。v27g 当前示例阈值为 19784，另保留阈值 16643 的已验证旧样本。本插件依用户要求固定 **16643**，不照搬高级球示例条件或 SysBot / 伊机控的传输时序。

设 `s` 为游戏回调收到投球 A 时的 RNG seed，偏移下限 / 上限为 `lo, hi`：

1. 对每一个 `d ∈ [lo, hi]`，候选摇球前 seed 为 `advance(s, d)`。
2. 此后四次 Random 的高 16 位必须**全部严格小于 16643**。
3. 各起点的四次抽取重叠，因此等价于：从 `advance(s, lo)` 开始，接下来的 `hi−lo+4` 次高 16 位全部通过。

例如上、下限都是 241，检查四次；242～245 检查连续七次。阈值相等也判失败。源码游戏依据为 [Cmd_handleballthrow](https://github.com/pret/pokefirered/blob/c75f352304d529f6ba92d4f74b9cf8b5c3810788/src/battle_script_commands.c)：普通球、最低普通可捕获种族捕获率 3、满 HP、无状态时 odds=1，整数平方根公式得到 16643。正常可捕获战斗中更高阈值也会通过这一组抽取；这个数学结论以实际抽取起点落在所设偏移带内为前提。

## 掌机端

生成目标轴保持从本轮标题 initial seed 起算。生成按键后驻留程序继续跟踪同一个 seed / index，但不自行启动捕获。用户在最终 Use 确认处，用 R＋SELECT 的一次新 SELECT 事件启用捕获；同一组合可取消。长按不会重新启动。

捕获搜索不再使用闪光、性格、物种或 IV 条件。其候选指向最早可能的摇球前 seed，按键截止位置为：

`候选绝对 advance − 捕获 Offset 下限 − 1`

其中最后的 1 是 VBlank 采样到回调输入之间的 RFU Random。预载的 affine 跳转用于快速从最新 seed 追上搜索，无远程采样延迟、毫秒速率换算或反复按键。按键回调恢复原函数后再次核对：实际 seed 必须恰为采样 seed 的一次后继，且回调场景未变；否则显示 D 并续搜。

默认捕获 Offset=241 是参考起点。v24 中 242～245 对应 SysBot 读数、50ms 按键及其采样路径；不能用这个记录替代本插件原生回调、单次 A 的实测校准。原工具的模型实测与本插件时序验收是两项证据。

启用后搜索至本轮绝对 advance 9999999，范围耗尽显示 E；重播种 / 倒退显示 F 并停止。取消也显示 E，可再次启用。一次投球后显示 C，等待用户核对结果，不自动多次投球或判断已经捕获。

## 验证边界

软件验证包括原工具成功向量 `seed=CA532E6A, lo=242, hi=245`；独立逐起点四次判定与合并偏移带比较；阈值边界；四种 ROM 地址配置；全部生成模型与 H1/H2/H4；生成后不重新安装的启用 / 取消 / 重启；RFU 检查、续搜、一次按键和保护区写入检查。

Unicorn 测试执行已编译的驻留代码，但代入游戏回调，**没有运行完整零售 ROM，也没有完成本插件的掌机投球时序验收**。实机步骤见 [HARDWARE_TEST_ZH.md](HARDWARE_TEST_ZH.md)。
