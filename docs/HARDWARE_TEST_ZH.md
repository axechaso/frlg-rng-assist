# FRLG RNG Assist 0.3.8 实机重测

目标是验证 seed、实际起点的 advances、倒计时和一次自动 A。**这轮先不要求闪光或指定 IV。** 软件模拟和正式版导出已经检查，掌机执行与时序仍待本轮验证。

已知实测：0.3.1 已在急冻鸟房间显示 seed 和倒计时，但旧版要求持续按 B，导致松开按键等待时没有自动 A。**这是旧版设计不符合预期，0.3.3 已移除 B 和所有三鸟站位检测。**本轮验证「走到位置 → 松开所有按键 → 到点自动 A」。

后续 0.3.3 测试出现 B 接近归零时退回 A 搜索，0.3.4 修正了提前丢弃目标，但真正错过后仍会停止。**0.3.5 改为实际错过后自动续搜，直到发送一次 A、原范围耗尽或计数失效。**本轮无需因为 D 而重启或重新注入。

0.3.5 的 D 只显示一帧，实测容易被直接看成 B 变 A；教学电视推进过头后也是如此。**0.3.6 将红色原因码在地图保留约一秒，之后再续搜；在电视里错过，会等返回地图后再开始这段提示。**同时增加奇偶颜色：与自动 A 时机不同奇偶为黄色，相同且当前可触发为绿色。

**0.3.7 修正「没错过、奇偶一致，到点仍反复 D11」的校验错误，0.3.8 保留该修正并新增 L+R 队尾 PID 显示。**旧版把通信阶段的一次正常 RNG 推进误判成了异常，取消了自动 A；现在按准确的后继 seed 校验，并保持原来的目标生成位置。先确认更新到 0.3.8，重新启动游戏再注入；仅更新 PC 插件不会替换掌机里已经注入的旧程序。这轮仍先允许非闪光、不限制性格和 IV，验证松开按键后能否实际自动开战。

## 1. 准备

1. PokeLDN 使用 **v0.39.1**。Wireless **1.8.0** 不需要因为插件另刷固件。
2. 本版仅支持 Switch 火红 / 叶绿英文或法文 rev 0A。选择与你实际游戏一致的火红 / 叶绿。
3. 先在尚未捕获的目标附近保存，尽量减少赶路；这次继续测试急冻鸟。队伍留一个位置，方便后续核对。查看 seed / PID 前，将 **OPTIONS → BUTTON MODE 设为 L/R 并保存**，避免 L/R 打开帮助页。
4. 完全关闭后重新启动游戏，清除其他 boosts；这一轮只注入本插件。
5. Plugins → Add a plugin，选择 `frlg-rng-assist-0.3.8.pokeplugin`。旧版使用更新文件入口，确认显示版本 **0.3.8** 并启用。

## 2. 在 PokeLDN 设置

Games → FireRed & LeafGreen → **RNG：搜索与到点自动 A**：

| 项目 | 首轮值 |
|---|---|
| 游戏、目标 | 与实机一致，这次选急冻鸟 |
| 起始 advance | `10000` |
| 结束 advance | `200000` |
| 性格 | 留空 |
| IV 下限 / 上限 | 默认 `0,0,0,0,0,0` / `31,31,31,31,31,31` |
| 允许非闪光 | **打开** |
| 安装并启用自动 A | **打开** |
| 仅预览配置 | **关闭** |

这个范围从标题重新播种的实际 seed 起算，不是从地图显示开始归零。如果从存档位置赶到目标要很久，把起始值改为 `20000` 或更大，重新启动后再安装。

## 3. 注入并观察计数

1. PokeLDN 点 Start；掌机进入 **Mystery Gift → Wonder Cards → Friend**，连接 **POKELDN**。
2. 等待 PokeLDN 显示安装回执已确认。日志应有 `Buffer script status: 0x524E4703`。没收到回执就不要当作安装成功。
3. 退出 Mystery Gift 回到标题，再正常选择继续游戏。**正常返回标题可保留注入；软重启或关闭游戏会清除，需重新安装。**不用把 PC 会话的 seed 带到地图。
4. 地图右上应出现两排数字。上排是当前 seed；下排先搜索 / 确认候选 `A…`，然后变成倒计时 `B…`。B 保留目标到指定时机，与自动 A 时机不同奇偶显示黄色，相同且当前回调可触发时显示绿色；这个比较已经扣除了遭遇偏移。实际错过后显示约一秒红色 D，再恢复 A 搜索或新 B。**颜色不检测三鸟站位，也不因颜色变化提前换目标。**
5. 按住 **L**，记录上排的初始 seed；下排是从这个 seed 起算的绝对 advances，进入地图时通常已经大于 0。松开 L 恢复倒计时；若此时错过，D 提示时间会等松开 L 后再计。若仍打开帮助页，确认 BUTTON MODE 已设为 L/R；本插件不单独读取 ZL。
6. **同时按住 L+R**：上排应改为白色的队尾宝可梦 8 位十六进制 PID，下排显示它的队伍位置，例如 `00000005`。松开 R、仍按 L，应返回初始 seed；两键松开应返回正常倒计时。单按 R 不切换显示。查看不暂停计时或自动 A，隐藏的 D 提示会保留。队伍为空或数量无效时显示 `FFFFFFFF` / `00000000`。捕获后回到地图也可直接查看，无需先保存；队伍满员、目标送进电脑时，显示的仍是原队尾。

若游戏卡住、黑屏或没有显示，停止这轮并记录发生在哪一步；重启后临时钩子会清除。不要在未核实结果时把这轮视为通过。

## 4. 停在正确位置，等待自动 A

**超梦：**在倒计时结束前走到超梦面前，按 A 开始对话，等待叫声和文字播放完，停在文字框等待下一次按键的位置。之后不要再按 A / B。到点应自动按一次 A 并进入战斗。

**三鸟（此次急冻鸟重测）：**在倒计时结束前走到急冻鸟面前，**松开所有按键，等到点自动按一次 A**。站位由你负责；插件不检查相邻、朝向、移动、目标对象或脚本阶段。倒计时结束时如果还没就位，这次 A 仍会发出。三鸟继续使用 2 advances 偏移，松开按键的实际生成时序需在本轮核对。

- `C0000001` 是已排定但尚未执行；`C0000000` 表示已经注入一次 A。**实际自动进入目标战斗**才是本轮按 A 流程的观察结果，不能只凭 C 宣称时序成功。
- D：本候选错过或未发送 A，具体原因见下表；**红色原因码在地图保留约一秒，再自动续搜**。提示期间实际 advances 仍推进，但不会搜索或发送 A。三鸟不会因为没按 B 或站位不符而拒绝 A。
- `D0000009`：实际推进已经跳过指定按键时机；提示结束后寻找原范围内更晚的候选。可以继续站定等待，不用重启。搜索沿用原筛选条件和初始 seed；下一个目标仍需等待倒计时。
- `E0000000`：范围内没有剩余可用目标，不会按 A。
- `F0000000`：计数失效，不会按 A。

出现 D 后观察是否恢复 A / B，并继续等后续候选。只有 E / F 或已经发送一次 A 后需要新一轮尝试时，才重新启动游戏并重新注入；不要在现有 resident hook 上重复安装。记录本轮日志、目标、范围、初始 seed、是否出现续搜以及最后状态。C 只确认插件发送了 A；如果 C 后游戏没响应，也要记录。

教学电视可用于测试提示：若还没越过目标，退出后应继续原 B 倒计时；若在电视中已超过目标，回到地图先显示红色 `D0000009` 约一秒，再续搜。电视中停留的时间不能提前消耗这段提示。若只想保留原目标，需要在到达自动 A 的 advance 前退出电视。

| D 末尾十进制原因码 | 含义 |
|---|---|
| `03` | 超梦脚本未进入指定按键等待阶段 |
| `04` | 不在正常地图回调 |
| `05` | 超梦的当前交互对象不符 |
| `09` | 已越过按 A 的 advance |
| `10` | 目标时刻主循环仍忙 |
| `11` | 执行前 RNG 不符合预期的一次正常推进（0.3.7 已修正正常推进的误报） |
| `12` | 排定的按键回调过期 |

## 5. 第一轮通过后再验证闪光

先在 PokeLDN 保存本次日志与安装报告。完成第一轮后重新启动游戏，重新安装；这次关闭「允许非闪光」，其他条件仍不限制。应搜索范围内的自然闪光候选，按相同等待方式触发。目标是否实际闪光要通过战斗或捕获核对，不能只看 C。

捕获核对（可选，但用于验证预测结果）：

1. 捕获后留在队伍，游戏内保存。
2. PokeLDN 选择 **RNG：核对捕获结果**。首轮允许非闪光的记录，在高级选项关联本次安装 JSON；没有关联报告时手动打开「允许非闪光」。
3. 高级选项输入刚才按 L 记录的初始 seed，并关联安装 JSON，才能核对绝对 advances 范围。
4. 再进入 Mystery Gift → Wonder Cards → Friend 完成读取。此读取会话不会延续上一轮 RNG。

报告仅核对最后保存的所选宝可梦。请同时记录实际自动开战的观察结果；没有初始 seed 时，报告不会宣称范围已验证。

## 回传结果的最少信息

- 游戏、语言、目标，PokeLDN / 插件版本。
- 是否收到 `0x524E4703`；是否出现 seed 和 B 倒计时。
- L 显示的初始 seed、范围、最后状态 C/D/E/F，以及是否实际自动开战。
- 若做了捕获核对，附本次安装 / 核对报告；无需提供密钥或整份存档。
